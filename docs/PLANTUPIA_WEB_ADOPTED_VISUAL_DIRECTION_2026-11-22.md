# Plantupia — visual direction adopted for website refinement
Date: 2026-11-22
Status: Working creative direction for the existing website; production deployment still requires review.

## Concept: Green Technology, experienced as one living system
The Plantupia product is not only an architecture portfolio or a shop. It connects real places, plant choices, products, ownership, ongoing care and technology. The visual website should let these relate without pretending that every page is a sensor dashboard or 3D simulation.

This is a **visual grammar**, not a new company slogan:
- **Place leads:** real source architectural proposals appear large and with their context intact.
- **Planting is a choice:** when several views share a place, the user can inspect and compare, not swipe past eight generic cards.
- **Material is specific:** the image's aspect ratio and composition matter; no forced equal-image crop.
- **Continuity matters:** the Shop and Living Systems are straightforward destinations, not hidden behind art direction.
- **One family:** forest, plaster and restrained olive; botanical material and typography carry the visual rhythm.
- **The + remains:** SiteIndex is the actual World Index, not a replacement hamburger.

## Applied to the *existing* site
- `HomeVisualField`: group the eight existing proposal images into the three true locations Pixels Mall, Audi Cairo and Villa 7. A main composition has real per-location image selection, image caption and project link.
- `MazalCaseStudy`: registered photographic overlay comparison with a keyboard/touch slider and the existing two proposal selectors, preserving the full nine-option wall.
- `SiteIndex`: lighten the reading area of the existing full-screen + overlay to let hierarchy and archive photography breathe, keeping existing links and navigation logic.

## Boundaries
All source images are design proposals or catalogue studies; do not present them as verified built installations, actual growth or live measurement.
No new public pages, labs, fictional data, changes to backend/Android, domain, or Production.
The working branch is a code-review and visual-acceptance surface for the real site, not a separate product.
