## Remaining cross-phase risks / follow-up

- push/root navigation policy has JVM characterization, but broader notification-routing and session-expiry centralization remain later shared-shell work;
- `PersonScreen` intentionally still owns privacy-state loading, private-request cancellation, block/report dialogs/transport, profile sharing, and message opening because those responsibilities cross later Privacy/Sharing/Messages boundaries; its first authored-Post page remains with `PersonStateOwner`, while the shared profile surface now owns older-page/repost state through `ProfileContentStateOwner` and stable AppContainer contracts;
- deprecated person/social-page compatibility aliases remain for `PersonScreen` and other downstream consumers until their designated feature boundaries migrate; completed People/Profile data/state owners and Profile self-screen use stable contracts/models directly;
- deprecated post-model compatibility aliases remain for not-yet-consolidated downstream consumers; stable Feed/Posts/Profile content code imports the feature post model directly;
- `NovaPostAuthor` intentionally remains shared in `core.network` because messaging and social-content code both consume that identity record; moving shared DTO ownership belongs to the later network/shared cleanup rather than this feature slice;
- Reels grids embedded in profile tabs remain Reels-owned and are intentionally not pulled into Profile consolidation;
- Stories currently has both stable feature domain records and legacy core transport records; this duplication is intentional only until the live Stories consumer moves to the stable boundary in the next slice;
- Phase 4 must consolidate the remaining social content one feature at a time without changing current product behavior;
- current hosted CI compiles the instrumentation APK but still does not execute instrumented tests on a device/emulator;
- the physical Samsung smoke matrix remains incomplete because the available device has a differently signed installed Nova package; and
- non-consolidated social/shared features may still contain historical naming or UI-owned repository patterns to be handled in their designated later phases.
