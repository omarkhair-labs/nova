## Scope and standard

The current product direction covers every exposed Android screen and its connected states, beginning with first launch, account creation and returning-user login. Creative opportunities are evaluated as changes to the real product: a more legible action, a recovered draft, a clearer permission, a meaningful illustration, or an easier return to the original task. The ambition is exceptional product craft. Awards are an aspiration, never a promised outcome or an acceptance criterion that can be established by code alone.

Plantupia keeps its own nature, architecture and lived-care identity. The existing Kotlin/Compose application, account and session ownership, Django APIs, media, messaging and safety engines remain the implementation foundation. The existing Play application identity stays unchanged. This scope does not authorize merging, deployment, database migration on a hosted service, payment changes or a store release. The independent public website and company dashboard require their own evidence; iOS remains outside this native implementation scope.

This document supplements the historical [screen closure ledger](../PLANTUPIA_SCREEN_CLOSURE_LEDGER.md), [conversion contract](../PLANTUPIA_PRODUCT_CONVERSION.md), [signature native note](PLANTUPIA_SIGNATURE_NATIVE_2026-11-25.md) and [art/journal note](PLANTUPIA_SIGNATURE_ART_AND_JOURNAL_2026-11-25.md). ## Changes made in this working increment

### Entry and form craftsmanship

Welcome uses a compact native botanical/architectural frame, clear account and login actions, a contextual delivery entry, and visible legal links. Registration presents account details followed by public identity, while using the same registration request. Login, registration and recovery share the typed email through explicit navigation. Passwords remain transient; password visibility and autofill semantics do not add new authentication providers.

Forms now include field feedback, keyboard actions, meaningful busy labels and error announcements. Recovery can return from the code stage to correct the email and invalidate stale code state. Shared buttons grow beyond their minimum height for larger text; Back controls support a disabled state. Shared loading/error/empty/retry components carry semantic information rather than relying solely on color or animation. Bottom-navigation icons are decorative beside their existing labels, so each tab has one spoken name; wrapped labels remain centered.

### Navigation and identity details

Literal corrupted question-mark navigation glyphs were replaced with the app-owned Back control in Settings, Edit Profile, visitor Profile, Create Post, Post Detail, Comments and Delivery connection. Directional settings indicators use the existing mirrored icon asset. Settings and Edit Profile content widths are bounded, auxiliary brand text yields at large text sizes, and About can scroll. Privacy and notification switches now identify the setting they control to accessibility services. Logout, legal URLs and central account ownership remain unchanged. The own-profile header reserves width for its two actions and places the title on its own line at large text. The Plants space hero uses a content-sized minimum height while its existing photo and overlay still fill the resulting bounds. Ask limits and scrolls its existing context section, consumes the IME insets at the route viewport and preserves space for the original keyed conversation. Its wording now describes the actual opt-in duration within the current chat.

### Recovery of unfinished work

Shop and creation-form state are scoped to the actual login generation. The same login can restore unfinished fields after Activity recreation; a different account or fresh login begins with clean component state. Shop no longer clears already-saveable delivery fields on every first composition. Cart data, prices, accepted receipts and submission progress are still loaded from the actual source; a restored draft cannot establish order success or payment.

The space/plant creation form restores existing text, type choice and open step. It waits for the current authorized space list before validating a restored selection, and drops a selection that is no longer writable. This does not persist a new photo permission, a server acknowledgment, a public-sharing consent or an automatic save. Photo selection and pending save behavior still require lifecycle QA.

### Verification and independent web corrections

Verified presentation/branding expectations in architecture scripts were brought into agreement with actual screens, while account, transport and ownership checks remain. Executable modes on the network and people checks were restored.

The independent public website received explicit chapter passages/targets and index navigation updates, plus smoke checks that match the actual shop collection and preserved route contracts. These changes are separate from native screen acceptance. They do not make the website deployed or the Android app verified.
