# Android — photograph, discovery, and field outline

Continues the integrated #333 branch. Android and the API needed by Android only.

The new plant editor begins with an optional real photo or live camera. The capture has a review/retake/use decision before the existing private creation or observation draft accepts it. File URIs for cover upload are limited to the application's own canonical temporary capture directory. Existing curated species selection remains explicitly self-reported or unknown.

The field record now supports a bounded interactive outline proposal as an alternative to manual tracing. The user marks included and excluded pixels in the upright original grid; the optional local OpenCV engine computes a colour/spatial prior, refines it with GrabCut, keeps the connected component containing the selected marks and checks a bounded simple polygon against the resulting component. It abstains when prompts overlap, contrast is insufficient or the region cannot be represented faithfully. A proposed outline is read-only until the user explicitly accepts it and supplies the part label. Signed proposals are bound to actor, event, source digest, method and exact vertices. Only the existing authorized trace endpoint persists accepted geometry and measured image features. Manual tracing remains available. A proposal does not recognize a species, infer plant presence or diagnose health.

The optional dependencies are installed in the isolated CI and core-root fixtures. The existing Living Systems feature flag remains off by default; no production migration, external model call, web changes or release. No model weights or customer images are added. Synthetic checks are not a field benchmark. The assisted pathway needs real annotated leaves, pots and cluttered rooms, measured operator correction time, device/large-text review and specialist acceptance. Species recognition, calibrated physical growth, actual camera pose/ARCore and spatial reconstruction remain separate open acceptance gates.
