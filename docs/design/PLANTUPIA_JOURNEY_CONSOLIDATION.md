# How a person moves between a plant, a place and a visit

Android integration review, 26 November 2026. The inventory below records the reachable product entry points and the decisions made for this increment.

| User intent | Existing paths examined | Decision and acceptance check |
|---|---|---|
| Find a plant in my space | Plants → Explore this place, floor drawing, recorded spatial plan, layout revisions, PLY viewer, room editor, AR floor survey | One room owns the revision, selection and actions. A projection change keeps the same plant selected. A revision change retains it only if present there. The list picker provides a touch-independent alternative to the drawing. A reconstruction file is an optional local source. AR supplies a candidate measurement in the editor. Only explicit save changes geometry. |
| See the light at a plant | Room daylight study, selected placement, API simulation | Open the study at the recorded coordinates of the selected plant. A study without a selection starts at the room centre. Changing the sample changes the title and scenario. Older layouts are read-only. No simulation writes a measurement or moves a plant. |
| Add or inspect a plant photograph | Creation photo, private care photo, first/change portrait, CameraX, gallery picker | The research-enabled journeys share camera permissions, framing, file choice, review and retry. Plant and care drafts retain explicit submission. A portrait has a separately labelled save and reuses the existing portrait endpoint. Gallery remains available when camera permission is denied. A prior dated photograph is available as a repeat-capture reference from the same plant's loaded history. |
| Identify a specimen | Creation species picker, unknown-type route, photo capture, screening of two classifiers | Keep confirmed identity, a user selection and unknown distinct. The screened classifiers failed taxon coverage or unknown rejection. Retain the add-and-inspect journey without a guessed identity or another discovery destination. |
| Understand a visit | Private PlantEvent history, event inspection, care guide, room revisions, Ask | Inspection reads the last room revision recorded by the visit timestamp alongside the existing botanical and care context. A later position or a missing placement contributes no location claim. This uses the existing scoped API and performs no provider call. General Ask retains its separate per-request context consent. |
| Move between calendar, care, history and Ask | Calendar summaries, plant chapters, personal and reviewed follow-ups, plant and general assistant | Planned entries open Care. Recorded entries read the selected plant's full day from the existing paginated event source, including dates older than the latest page. The same sheet can open its plant's history. From a calendar day, explicit consent scopes the shared observations to that day. No navigation action records an event or sends a question. |
| Buy and follow an order | Shop root → PlantupiaStoreShop → cart → checkout → orders, notification deep links, old PlantupiaQaShop implementation | The root reaches one commercial checkout. No production caller of the legacy QA composable was found. Retain the test fixture until its dependants are reviewed. Existing carts, notification targets and delivery state remain authoritative. |
| Find my personal and public records | ProfileScreen, private world, Circle profile, profile editing, messages and settings | The updated integration branch already distinguishes private spaces from explicit public identity in one account. Preserve those audience boundaries and the existing profile route. No second profile was introduced. |

A dated inspection now resolves its previous distinct photo on an earlier day from the same plant, including older pages. The existing comparison, alignment and calibrated measurements take those two event IDs. In the room, an explicitly selected historical revision can run a daylight scenario against its saved windows. A stale current-layout request still requires a refresh. The floor survey can return a bounded, temporary ARCore feature-point preview alongside its estimated dimensions. The room editor does not persist the points or camera frames.

Private profile thumbnails now open the authenticated plant and individual place names focus that space. The existing delivered-order link already opens the connected plant. These entry points continue to use one inventory.

The optional inspection outline starts with a fixed-frame GrabCut candidate or points marked on the image. Both use the same operator review and signed acceptance. Running the automatic polygon path on the 48 photographs from the existing Oxford flower benchmark produced 43 candidates and five abstentions. Mean intersection over union among the candidates was 0.850, with a minimum of 0.051. These are foreground regions on flower images. The recorder checks the boundary and labels the visible part.

The camera inventory above covers private plant journeys. QR handover, AR pose tracking, video calls and deliberately published social media have different session, permission and audience requirements. The existing specialized capture clients continue to own those tasks. Wider social, commerce and profile visual acceptance remains open.

The Android instrumentation journey exercises plan, perspective, plant selection, revision browsing, local reconstruction, direct sunlight and private capture. The Django regression test checks absent, earlier and moved placements and cross-account access. A physical-phone pass must still exercise camera, tracking loss, back, RTL, large type and the isolated QA service with a real device. Technical validation and field acceptance are recorded separately in the PR.

For a connected, authorized test phone, use the CI artifact named `plantupia-living-qa-usb-8876` with `scripts/plantupia_local_phone_qa.ps1 -ApkPath <extracted-apk> -LivingSystems`. This uses the dedicated `.qa.living` application identity, a fresh SQLite database and localhost over USB. The default QA launcher still targets port 8765.
