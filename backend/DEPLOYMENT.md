# Nova production deployment

Nova's hosted environment is designed for Railway:

- Django served through Daphne/ASGI for HTTP + WebSockets
- Railway PostgreSQL
- Railway Redis for shared realtime state and password-recovery challenges
- Railway S3-compatible Storage Bucket for avatars, posts and message media
- HTTPS/WSS public domain generated by Railway

## Railway service layout

Create one Railway project with four resources:

1. A service deployed from the `omarkhair70-droid/nova` GitHub repository.
2. A PostgreSQL database.
3. A Redis database.
4. A Storage Bucket.

For the app service, set the Root Directory to `/backend` so Railway builds `backend/Dockerfile`.

## Required app variables

Set these on the Django app service:

```text
DJANGO_ENV=production
DJANGO_DEBUG=0
DJANGO_SECRET_KEY=<long-random-secret>
DATABASE_URL=${{Postgres.DATABASE_URL}}
REDIS_URL=${{Redis.REDIS_URL}}
DJANGO_ALLOWED_HOSTS=${{RAILWAY_PUBLIC_DOMAIN}}
```

Inject/reference the Storage Bucket credentials into the app service using these names:

```text
AWS_ENDPOINT_URL
AWS_ACCESS_KEY_ID
AWS_SECRET_ACCESS_KEY
AWS_S3_BUCKET_NAME
AWS_DEFAULT_REGION
AWS_S3_URL_STYLE
```

Railway exposes matching S3-compatible credentials from the bucket Credentials panel.

For Firebase push delivery, also configure:

```text
FIREBASE_SERVICE_ACCOUNT_JSON=<firebase-service-account-json>
```

For V10 password-recovery email delivery, configure an SMTP account on the Django service:

```text
EMAIL_HOST=<smtp-host>
EMAIL_PORT=587
EMAIL_USE_TLS=1
EMAIL_USE_SSL=0
EMAIL_HOST_USER=<smtp-username>
EMAIL_HOST_PASSWORD=<smtp-password-or-app-password>
DEFAULT_FROM_EMAIL=<verified-sender-address>
```

Use `EMAIL_USE_SSL=1` and `EMAIL_USE_TLS=0` instead when the SMTP provider requires implicit SSL (commonly port 465). Never commit SMTP credentials to the repository.

## Deploy lifecycle

The production Docker image starts by running migrations and static collection, then launches Daphne so the same process serves REST and WebSocket traffic:

```text
python manage.py migrate --noinput
python manage.py collectstatic --noinput
daphne -b 0.0.0.0 -p $PORT nova_backend.asgi:application
```

After the deployment is active, generate a Railway public domain and verify:

```text
https://<railway-domain>/api/v1/health/
```

Expected response:

```json
{"status":"ok","service":"nova-api"}
```

Authenticated conversation WebSockets are available at:

```text
wss://<railway-domain>/ws/conversations/<conversation-id>/
Authorization: Bearer <access-token>
```

## Redis and realtime

When `REDIS_URL` is present, Nova uses `channels_redis` so HTTP/ASGI workers and replicas share realtime conversation state. V10 also stores short-lived password-reset challenges and request cooldowns in Redis. If Redis is unavailable in local development, password recovery falls back to process-local temporary storage; production should keep Redis attached.

## Local development

`docker compose up --build` can use local PostgreSQL and local media files. Production switches to Railway PostgreSQL, Redis and object storage through environment variables.

## Android handoff

The Android app uses the Railway service directly:

```text
https://<railway-domain>/api/v1/
wss://<railway-domain>/ws/
```

`adb reverse` and a running laptop are not required for normal app use.
