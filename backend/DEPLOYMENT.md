# Nova production deployment

Nova's hosted environment is designed for Railway:

- Django served through Daphne/ASGI for HTTP + WebSockets
- Railway PostgreSQL
- Railway Redis for shared realtime state, call liveness and password-recovery challenges
- Railway S3-compatible Storage Bucket for avatars, posts and message media
- HTTPS/WSS public domain generated by Railway

## Railway service layout

Create one Railway project with four resources:

1. A service deployed from the `omarkhair70-droid/nova` GitHub repository.
2. A PostgreSQL database.
3. A Redis database.
4. A Storage Bucket.

For the app service, set the Root Directory to `/backend` so Railway builds `backend/Dockerfile`.

## Required app variables

Set these on the Django app service:

```text
DJANGO_ENV=production
DJANGO_DEBUG=0
DJANGO_SECRET_KEY=<long-random-secret>
DATABASE_URL=${{Postgres.DATABASE_URL}}
REDIS_URL=${{Redis.REDIS_URL}}
DJANGO_ALLOWED_HOSTS=${{RAILWAY_PUBLIC_DOMAIN}}
```

Inject/reference the Storage Bucket credentials into the app service using these names:

```text
AWS_ENDPOINT_URL
AWS_ACCESS_KEY_ID
AWS_SECRET_ACCESS_KEY
AWS_S3_BUCKET_NAME
AWS_DEFAULT_REGION
AWS_S3_URL_STYLE
```

Railway exposes matching S3-compatible credentials from the bucket Credentials panel.

For Firebase push delivery, also configure:

```text
FIREBASE_SERVICE_ACCOUNT_JSON=<firebase-service-account-json>
```

For password-recovery email delivery, configure an SMTP account on the Django service:

```text
EMAIL_HOST=<smtp-host>
EMAIL_PORT=587
EMAIL_USE_TLS=1
EMAIL_USE_SSL=0
EMAIL_HOST_USER=<smtp-username>
EMAIL_HOST_PASSWORD=<smtp-password-or-app-password>
DEFAULT_FROM_EMAIL=<verified-sender-address>
```

Use `EMAIL_USE_SSL=1` and `EMAIL_USE_TLS=0` instead when the SMTP provider requires implicit SSL (commonly port 465). Never commit SMTP credentials to the repository.

## Voice/video call networking

Nova uses WebRTC for audio/video media and Django Channels for authenticated call signaling. ICE server configuration is delivered to Android by the backend instead of being hard-coded into the APK.

The backend accepts an optional `NOVA_CALL_ICE_SERVERS_JSON` environment variable. It must contain a JSON array of ICE server objects. For example, a STUN + TURN configuration looks like:

```json
[
  {
    "urls": ["stun:stun.example.net:3478"]
  },
  {
    "urls": [
      "turn:turn.example.net:3478?transport=udp",
      "turn:turn.example.net:3478?transport=tcp",
      "turns:turn.example.net:5349?transport=tcp"
    ],
    "username": "<turn-username>",
    "credential": "<turn-password>"
  }
]
```

In Railway, store the entire compact JSON array as the value of:

```text
NOVA_CALL_ICE_SERVERS_JSON=<json-array>
```

Never commit TURN credentials to the repository.

If `NOVA_CALL_ICE_SERVERS_JSON` is absent or invalid, Nova falls back to a public STUN server so development and basic device testing can proceed. STUN-only is not considered production-reliable: direct WebRTC connectivity can fail behind restrictive NATs, carrier networks, enterprise Wi-Fi or firewalls. Configure at least one working TURN server before treating voice/video calls as broadly production-ready.

Call signaling uses:

```text
wss://<railway-domain>/ws/calls/<call-id>/
Authorization: Bearer <access-token>
```

Incoming calls are woken with high-priority short-lived Firebase data messages. PostgreSQL stores durable call state, while Redis carries Channels traffic and a short liveness lease. The Android signaling client refreshes that lease while a call socket is alive so abandoned `active` rows can be released instead of leaving a user permanently busy after a crash or network loss.

## Deploy lifecycle

The production Docker image starts by running migrations and static collection, then launches Daphne so the same process serves REST and WebSocket traffic:

```text
python manage.py migrate --noinput
python manage.py collectstatic --noinput
daphne -b 0.0.0.0 -p $PORT nova_backend.asgi:application
```

After the deployment is active, generate a Railway public domain and verify:

```text
https://<railway-domain>/api/v1/health/
```

Expected response:

```json
{"status":"ok","service":"nova-api"}
```

Authenticated conversation WebSockets are available at:

```text
wss://<railway-domain>/ws/conversations/<conversation-id>/
Authorization: Bearer <access-token>
```

## Redis and realtime

When `REDIS_URL` is present, Nova uses `channels_redis` so HTTP/ASGI workers and replicas share realtime conversation and call state. Password recovery stores short-lived challenges and request cooldowns in Redis, while calls use Redis for signaling transport and liveness leases. If Redis is unavailable in local development, password recovery falls back to process-local temporary storage; production should keep Redis attached.

## Local development

`docker compose up --build` can use local PostgreSQL and local media files. Production switches to Railway PostgreSQL, Redis and object storage through environment variables.

## Android handoff

The Android app uses the Railway service directly:

```text
https://<railway-domain>/api/v1/
wss://<railway-domain>/ws/
```

`adb reverse` and a running laptop are not required for normal app use.

## V1 release checklist

Before shipping a production build:

- Confirm Nova CI is green, including `lintRelease` and `assembleRelease`.
- Build/sign the production artifact with the real Android signing key; never commit the keystore or passwords.
- Confirm the Firebase Android app is registered for `com.omarkhair70.nova` and the production `google-services.json` is supplied locally/through the release environment, not committed.
- Confirm Railway health returns `200` and PostgreSQL, Redis and object storage are attached.
- Confirm `DJANGO_DEBUG=0`, a strong `DJANGO_SECRET_KEY`, production allowed hosts and production media credentials.
- Confirm SMTP password recovery and Firebase push delivery from a real device.
- Confirm a working TURN server is present in `NOVA_CALL_ICE_SERVERS_JSON` before relying on calls across arbitrary networks.
- Run a two-physical-device smoke pass: register/login, profile/avatar, follow/block/report, post/comment/delete confirmation, direct messaging/media/voice notes/search, push open, voice call, video call, network handoff and video PiP.
- Verify Terms/Privacy copy and store disclosures with appropriate legal/product review before public distribution.
- Increment `versionCode` for every store upload and set the intended public `versionName`.
